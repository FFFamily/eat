# 用户体系代码逻辑分析与企业级缺口清单（hs_admin_user / hs_user）

> 范围：仅基于 `hs_admin_user` 与 `hs_user` 模块源码与 MyBatis XML，整理当前用户逻辑、关系模型，并给出企业级用户体系的缺失模块与可落地执行清单。

## 1. 模块现状概览

### 1.1 hs_admin_user（后台管理用户）
- 核心实体：`AdUser`、`AdRole`、`AdPermission`、`AdDepartment`、`AdUserRole`、`AdRolePermission`、`AdOperationLog`。
- 典型能力：
  - 管理员用户的增删改查、状态切换、密码重置、角色分配。
  - 角色管理、权限管理、部门树管理。
  - 操作日志记录、查询、统计、清理。
- 权限模型：典型 RBAC（角色-权限），权限支持菜单树结构（`parentId` + `type`）。

### 1.2 hs_user（业务用户/客户账号）
- 核心实体：`Account`、`AccountType`、`Address`、`AccountBankCard`、`AccountServiceScope`、`AccountCustomer`、`Processor`、`Role`、`UserRole`。
- 典型能力：
  - 账号创建、状态切换、业务类型变更、账号生成规则。
  - 地址管理（默认地址逻辑）、银行卡管理（默认卡逻辑）。
  - 客户关系（服务商与客户的关系映射）。
  - 服务范围（省/市/区）管理。
  - 经办人管理。
- 权限模型：有 `Role` / `UserRole` 实体，但缺少权限实体与服务逻辑实现。

## 2. 当前用户逻辑梳理（可执行视角）

### 2.1 管理员用户流（hs_admin_user）
1. **创建用户**：校验用户名唯一 → 密码加密（`PasswordUtil.encode`）→ 默认状态 → 保存。
2. **更新用户**：校验存在 → 保护超级管理员 → 校验用户名/手机号唯一 → 如传入密码则加密 → 保存。
3. **重置/修改密码**：通过 MD5 方式保存新密码（与创建时加密方式不一致）。
4. **角色分配**：先软删除旧角色关联 → 再插入新角色关联。
5. **权限分配**：先软删除旧权限关联 → 再插入新权限关联。
6. **部门管理**：支持树结构（`parentId`），无循环校验。
7. **操作日志**：异步记录、分页查询、按时间清理。

### 2.2 业务账号流（hs_user）
1. **账号创建**：校验用户名/手机号唯一 → 密码加密（AES）→ 账号状态默认启用 → 业务类型默认供货商。
2. **账号更新**：直接覆盖密码（无空值判断） → 保存。
3. **账号编号生成**：按账号类型统计数量生成 `CODE+00001` 规则 → 存在并发冲突风险。
4. **地址管理**：新增时判断是否首地址 → 默认地址逻辑；设置默认地址时，先清零再置默认。
5. **银行卡管理**：默认卡校验（同一用户最多 1 张默认卡）。
6. **客户关系**：同一账户不能重复添加同一客户；不能自己加自己。
7. **服务范围**：先删除再批量新增。
8. **经办人**：分页查询、按账号查询。

## 3. 作为企业级用户体系的缺失模块

> 以“企业级多组织、多角色、多场景安全管控”为标准，当前模块缺失如下关键能力：

### 3.1 多租户/组织体系
- 租户（Tenant）管理与隔离（数据、权限、配置）。
- 组织架构与成员关系（组织、岗位、成员、汇报线、成员类型）。
- 企业主体与工商信息（法人、营业执照、税务信息、认证状态）。

### 3.2 统一认证与登录体系
- 登录鉴权中台（Token/Session、Refresh Token 生命周期、失效策略）。
- 多因子认证（MFA/OTP/短信/邮箱）。
- SSO（OIDC/SAML）与第三方登录集成。
- 设备管理、登录记录、异常登录告警。

### 3.3 授权与数据权限
- 统一的权限资源模型（资源、动作、范围）。
- 细粒度数据权限（行级/字段级/部门级数据隔离）。
- 角色继承、临时授权、权限审计与变更审批。

### 3.4 用户生命周期与运营
- 注册、邀请、审批、激活、冻结、注销流程。
- 用户自助中心（安全设置、账号绑定、隐私设置）。
- 客户/服务商分层与标签体系（客户等级、信用额度）。

### 3.5 安全与合规
- 密码策略（强度、过期、历史禁用、重试锁定）。
- PII/敏感字段加密、脱敏展示、数据留存策略。
- 审计合规：安全审计、访问日志、行为分析。

## 4. 可执行落地清单（建议按阶段推进）

### P0：安全与一致性治理（优先级最高）
- 统一密码策略：更换为不可逆哈希（BCrypt/Argon2），移除 AES/MD5；补充密码强度规则。
- 统一账号模型字段：明确 `type` vs `accountTypeId` 的职责，统一命名与约束。
- 强化唯一约束：用户名、手机号、账号编号、角色编码等建立数据库唯一索引。
- 修复 SQL 注入风险与软删除过滤缺失（详见优化说明文档）。

### P1：企业组织与授权体系
- 新增租户与组织成员表：`tenant`、`org_unit`、`org_member`、`member_role`。
- 统一权限资源模型：`permission_resource`、`permission_action`、`role_permission`。
- 账号 → 组织 → 数据域的授权链路（支持数据范围控制）。

### P2：认证与运营体系
- 登录/会话中心：Token 生命周期、刷新机制、设备管理。
- 登录安全：MFA、异常登录告警、验证码策略。
- 用户生命周期：注册→审核→启用→冻结→注销。
- 审计与报表：登录日志、权限变更、管理员操作留痕。

### P3：平台化能力与合规
- SSO（OIDC/SAML）对接。
- 敏感数据治理（字段级加密/脱敏/权限控制）。
- 数据保留与隐私合规（导出审批、数据删除策略）。

## 5. 输出物（可交付）
- 数据库设计：租户、组织、成员、权限、认证相关表设计文档。
- API 清单：账号生命周期、角色/权限、组织关系、登录安全。
- 权限模型说明：资源-动作-范围矩阵。
- 安全策略说明：密码策略、MFA、异常登录处理流程。
